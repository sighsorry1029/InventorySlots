# Item sharing checks

Run `dotnet run --project build/ItemLinkTests -c Debug` (PowerShell 7 is used by the cursor-source extraction step).

The tests compile the production snapshot codec/store and extract the actual chat-focus, cursor-predicate and mouse-click lease methods from `ItemLinkUi.cs`. Cursor checks simulate the Unity/input boundaries for feature on/off, absent/hidden/inactive chat, blocked UI, controller-only input and Mouse0 down/held/up/release. The extractor fails if selected methods disappear; it expects ordinary block bodies without braces in string literals.

Item-link UI checks exercise the extracted middle-click acquisition/consumption/refocus methods with EventSystem-before-mod and mod-before-EventSystem ordering. They cover repeated focus polls and an InputSystem press observed in a later render frame, held/released presses, stale focus, feature toggling, and preservation of draft/selection without reopening on Escape/Enter or after another UI edits the text. Layout checks cover inherited channel-color markup, stable chat-edge placement during loading, cramped/right-edge chat, and live Canvas sorting without changing native canvases. Unity layout, rendering, TMP hit testing and the real input loop still require in-game checks.

`build/HarmonySmoke` separately applies the compiled cursor transpiler to original Valheim `GameCamera.UpdateMouseCapture` IL. It verifies a single camera-local predicate insertion and preservation of every original instruction, including Ctrl+F1 and the native menu/radial paths. It does not install Harmony detours or execute Unity.

Clan checks compile the production optional adapter and source-extracted RPC callbacks, with transport, platform permission callbacks and the Clan API simulated at their boundaries. They cover absent/late/disabled Clan, one subscription per binding, authenticated sender versus own accepted echo, unsent/private/public offers, outsider requests, membership changes during asynchronous permission checks, scope cleanup, native re-sharing and repeated teardown. Clan's separate `Tests/ClanChatIntegrationSmoke.ps1` exercises the real API formatter and authorization policy with network/identity boundary stubs. Neither harness is an actual cross-mod game session.

Manual game checks still needed: chat hover and middle-click pinning with inventory closed, close/share buttons through mouse release, Escape/Enter, feature toggling, keyboard/mouse versus controller, and Clan present/absent with KeepOpen/CloseAfterSend. Test matching Clan v14 host/dedicated clients, duplicate display names, primary/Guest changes, kick/leave while a request is pending, disconnect/reconnect, and both Clan-only and native `/s`/`/w` channels. Do not mix old/new Clan protocol builds.
